# Шаблон настройки Claude Code для любого проекта

## Быстрый старт для нового проекта

### 1. Создать CLAUDE.md в корне проекта

```markdown
# [Название проекта] - Контекст для Claude

## Цель проекта
[В 2-3 предложениях: что делает проект, для кого, зачем]

## Архитектура
[Краткая схема: какие основные модули/компоненты, как они связаны]

## Ключевые файлы
- `src/main.py` - точка входа
- `src/core/` - основная бизнес-логика
- `tests/` - тесты

## Технологии
- Python 3.11 / Node.js 20 / Go 1.21
- Framework: Django / FastAPI / Express / Next.js
- DB: PostgreSQL / MongoDB / Redis
- Деплой: Docker / Kubernetes / Vercel

## Команды для разработки
```bash
# Установка
npm install / pip install -r requirements.txt / go mod download

# Запуск
npm run dev / python main.py / go run main.go

# Тесты
npm test / pytest / go test ./...

# Сборка
npm run build / docker build -t myapp .
```

## Стиль кода
- Форматирование: prettier / black / gofmt
- Линтинг: eslint / ruff / golangci-lint
- Типы: TypeScript / mypy / встроенные в Go

## Важные детали
[Специфика проекта: требования к безопасности, особенности API, ограничения]

## Частые проблемы
1. [Проблема] → [Решение]
2. ...
```

### 2. Создать .claude/settings.json

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "src/",
        "hooks": [
          {
            "type": "command",
            "comment": "Автоформатирование после изменения кода",
            "command": "cd $PROJECT_ROOT && (npm run format 2>/dev/null || black . 2>/dev/null || gofmt -w . 2>/dev/null || true); exit 0"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "bash",
        "hooks": [
          {
            "type": "command",
            "comment": "Блокировка опасных команд",
            "command": "sh -c 'if echo \"$ARGUMENTS\" | grep -qE \"(rm -rf /|DROP DATABASE|--force.*main|--force.*master)\"; then echo \"⛔ Опасная команда заблокирована\" >&2; exit 2; fi'"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "comment": "Показать статус git после завершения",
            "command": "git status --short 2>/dev/null | head -10 || true; exit 0"
          }
        ]
      }
    ]
  }
}
```

### 3. Полезные slash команды

#### .claude/commands/test.md
```markdown
---
description: Запустить тесты проекта
---

Запусти тесты проекта соответствующей командой:
- Node.js: npm test
- Python: pytest -v
- Go: go test ./...

Если есть ошибки, проанализируй и предложи исправления.
```

#### .claude/commands/review.md
```markdown
---
description: Ревью последних изменений
---

Проанализируй последний коммит или незакоммиченные изменения:

1. Запусти git diff или git show HEAD
2. Проверь:
   - Качество кода
   - Потенциальные баги
   - Безопасность
   - Производительность
   - Стиль кодирования
3. Дай конкретные рекомендации

Будь конструктивен, не придирайся к мелочам.
```

#### .claude/commands/debug.md
```markdown
---
description: Помощь в отладке с контекстом
---

Помоги отладить проблему. Нужно:

1. Изучить стек ошибки из $ARGUMENTS
2. Найти релевантные файлы
3. Прочитать код в местах ошибки
4. Проверить типичные причины (null/undefined, race conditions, типы данных)
5. Предложить исправление с объяснением

Спроси уточняющие вопросы, если контекста недостаточно.
```

#### .claude/commands/refactor.md
```markdown
---
description: Рефакторинг кода с сохранением функциональности
---

Отрефактори код из $ARGUMENTS:

1. Прочитай текущую реализацию
2. Определи code smells (дублирование, сложность, плохие имена)
3. Предложи улучшения:
   - Разбить большие функции
   - Выделить общую логику
   - Улучшить именование
   - Упростить условия
4. Реализуй изменения
5. Убедись, что тесты проходят

Не меняй публичные API без необходимости.
```

#### .claude/commands/feature.md
```markdown
---
description: Реализация новой фичи с планированием
---

Реализуй новую фичу: $ARGUMENTS

План работы:
1. **Анализ**: изучи существующий код, найди где интегрировать
2. **Дизайн**: предложи архитектуру (не переусложняй)
3. **Реализация**:
   - Основная логика
   - Обработка ошибок
   - Валидация входных данных
4. **Тесты**: покрой основные сценарии
5. **Документация**: обнови README/комментарии если нужно

Спрашивай о деталях, если требования неполные.
```

#### .claude/commands/optimize.md
```markdown
---
description: Оптимизация производительности
---

Оптимизируй производительность кода из $ARGUMENTS:

1. Профилируй текущую реализацию (добавь замеры времени)
2. Найди узкие места:
   - N+1 запросы к БД
   - Лишние циклы
   - Избыточные вычисления
   - Большие объекты в памяти
3. Предложи оптимизации:
   - Кэширование
   - Батчинг
   - Индексы БД
   - Асинхронность
4. Измерь улучшение

Оптимизируй только если есть реальная проблема.
```

#### .claude/commands/security.md
```markdown
---
description: Аудит безопасности кода
---

Проведи security audit для $ARGUMENTS:

Проверь на уязвимости:
1. **Injection**: SQL, NoSQL, Command, XSS
2. **Auth/AuthZ**: проверка прав, обход авторизации
3. **Sensitive data**: логирование паролей, хранение секретов
4. **Input validation**: отсутствие проверок, type confusion
5. **Dependencies**: известные уязвимости в зависимостях
6. **Rate limiting**: DoS, brute force
7. **CSRF/SSRF**: межсайтовые атаки

Для каждой проблемы дай:
- Описание риска
- Пример эксплуатации
- Исправление
```

#### .claude/commands/docs.md
```markdown
---
description: Генерация/обновление документации
---

Обнови документацию для $ARGUMENTS:

1. Прочитай код модуля/функции
2. Создай/обнови:
   - Docstrings / JSDoc комментарии
   - README секции
   - API документацию
   - Примеры использования
3. Используй стиль:
   - Кратко и по делу
   - Примеры кода
   - Типы параметров и возвращаемых значений
   - Возможные ошибки

Избегай очевидных комментариев типа "эта функция делает X" когда название уже говорит об этом.
```

### 4. Hooks для автоматизации

#### .claude/hooks/format-code.sh
```bash
#!/bin/bash
# Автоформатирование после редактирования кода

cd "$PROJECT_ROOT" || exit 0

# Определяем язык проекта и форматируем
if [ -f "package.json" ]; then
    npm run format 2>/dev/null || npx prettier --write . 2>/dev/null || true
elif [ -f "pyproject.toml" ] || [ -f "requirements.txt" ]; then
    black . --quiet 2>/dev/null || true
    isort . --quiet 2>/dev/null || true
elif [ -f "go.mod" ]; then
    gofmt -w . 2>/dev/null || true
fi

exit 0
```

#### .claude/hooks/run-tests.sh
```bash
#!/bin/bash
# Запуск тестов после изменений

cd "$PROJECT_ROOT" || exit 0

echo "🧪 Запускаю тесты..."

if [ -f "package.json" ]; then
    npm test 2>&1 | head -20
elif [ -f "pyproject.toml" ] || [ -f "requirements.txt" ]; then
    pytest -q 2>&1 | head -20
elif [ -f "go.mod" ]; then
    go test ./... 2>&1 | head -20
fi

exit 0
```

#### .claude/hooks/check-secrets.sh
```bash
#!/bin/bash
# Проверка, что не коммитим секреты

cd "$PROJECT_ROOT" || exit 0

# Паттерны секретов
PATTERNS=(
    "password\s*=\s*['\"][^'\"]+['\"]"
    "api_key\s*=\s*['\"][^'\"]+['\"]"
    "secret\s*=\s*['\"][^'\"]+['\"]"
    "token\s*=\s*['\"][^'\"]+['\"]"
    "-----BEGIN PRIVATE KEY-----"
)

for pattern in "${PATTERNS[@]}"; do
    if git diff --cached | grep -iE "$pattern"; then
        echo "⚠️  ВНИМАНИЕ: Возможный секрет в коммите!" >&2
        echo "Проверьте изменения перед пушем" >&2
    fi
done

exit 0
```

### 5. Шпаргалка по эффективным практикам

#### Работа с большими задачами
```
1. Начни сессию: /rename проект-большая-фича
2. Разбей на подзадачи: "Распиши план реализации в виде чеклиста"
3. Работай по частям с /compact между этапами
4. Финальный /clear перед следующей фичей
```

#### Отладка сложных багов
```
1. Опиши проблему детально (что ожидал, что получил, стек ошибки)
2. Покажи минимальный пример воспроизведения
3. Укажи, что уже пробовал
4. Попроси Claude прочитать релевантные файлы и объяснить поток выполнения
```

#### Изучение нового кодбейса
```
1. "Изучи структуру проекта, расскажи основные модули"
2. "Объясни как работает [конкретная фича]"
3. "Найди где обрабатывается [какое-то событие]"
4. "Нарисуй flow данных от [A] до [B]"
```

#### Code review
```
1. "Посмотри последний коммит, найди потенциальные проблемы"
2. "Проверь на security issues в файле X"
3. "Оцени читаемость и поддерживаемость модуля Y"
```

#### Рефакторинг
```
1. "Найди дубликаты кода в директории src/"
2. "Эта функция слишком сложная, упрости её"
3. "Выдели общую логику из этих трёх файлов"
```

### 6. Типичные антипаттерны (чего НЕ делать)

❌ **Не давай расплывчатые задачи**
```
Плохо: "Улучши код"
Хорошо: "Функция process_data() в src/core.py работает 5 секунд на 1000 элементах.
         Оптимизируй до <1 секунды, используя батчинг или кэширование"
```

❌ **Не теряй контекст**
```
Плохо: Начинать каждый новый вопрос с /clear
Хорошо: Использовать /compact когда контекст становится большим,
        /clear только между крупными независимыми задачами
```

❌ **Не перегружай один промпт**
```
Плохо: "Добавь авторизацию, оптимизируй БД, напиши тесты, обнови README"
Хорошо: Разбей на этапы, делай по одному, используй /todos для трекинга
```

❌ **Не полагайся на память между сессиями без /resume**
```
Плохо: Закрыл терминал и ожидаешь, что Claude помнит вчерашний контекст
Хорошо: /rename важные сессии, /resume для продолжения работы
```

### 7. Интеграция в повседневный workflow

#### Утренний чеклист
```bash
1. cd ~/projects/myapp
2. /resume myapp  # продолжить вчерашнюю работу
3. /todos  # проверить что осталось
4. Продолжить с того места, где остановился
```

#### Перед коммитом
```bash
1. /review  # проверить изменения
2. Claude даст фидбек
3. Исправить замечания
4. git add . && git commit -m "..."
```

#### Новая фича
```bash
1. /clear  # свежий старт
2. /rename проект-фича-название
3. "Реализуй [описание фичи]"
4. Работаешь с Claude шаг за шагом
5. /compact если контекст растёт
6. После завершения можешь /clear или продолжить
```

#### Debugging session
```bash
1. /debug "StackTrace: ..."
2. Claude анализирует и предлагает фиксы
3. Применяешь исправления
4. Тестируешь
5. Если всё ок - /clear для следующей задачи
```

### 8. Оптимизация стоимости

- Используй **Sonnet** (по умолчанию) для 95% задач
- Переключайся на **Opus** только для:
  - Сложных архитектурных решений
  - Рефакторинга большой кодовой базы
  - Отладки хитрых багов
- Используй **Haiku** для:
  - Простых правок
  - Форматирования
  - Тривиальных вопросов
- **Регулярно делай /compact** - экономит до 70% токенов
- **Давай точные промпты** - меньше итераций = меньше токенов

## Заключение

Эффективность работы с Claude Code =
  **Хороший контекст** (CLAUDE.md) +
  **Автоматизация** (hooks) +
  **Переиспользуемые команды** (slash) +
  **Управление памятью** (/compact, /resume)

Начни с создания CLAUDE.md в каждом проекте - это даст максимальный эффект с минимальными усилиями.
