# Рефакторинг

Отрефактори код из: $ARGUMENTS

## Процесс:

### 1. Анализ текущего состояния
- Прочитай текущую реализацию
- Пойми что делает код
- Найди существующие тесты

### 2. Выяви code smells
- **Дублирование**: повторяющаяся логика
- **Сложность**: функции >50 строк, вложенность >3
- **Плохие имена**: x, tmp, data, manager
- **Магические числа**: хардкод значений
- **Длинные параметры**: >4 параметров
- **Большие классы**: >300 строк, слишком много ответственности

### 3. Предложи улучшения
- Разбей большие функции на маленькие с понятными именами
- Выдели общую логику в утилиты
- Улучши именование (говорящие имена)
- Упрости условия (early returns, guard clauses)
- Примени паттерны где уместно (не перебарщивай!)

### 4. Реализуй изменения
- Делай маленькие шаги
- После каждого шага проверяй что тесты проходят
- Если тестов нет - сначала покрой текущую функциональность

### 5. Проверка
- Все тесты зелёные
- Функциональность не изменилась
- Код стал проще и понятнее

## Правила:
- Не меняй публичные API без крайней необходимости
- Сохраняй обратную совместимость
- Если рефакторинг большой - делай поэтапно
- Рефакторинг != добавление фич (делай что-то одно)
