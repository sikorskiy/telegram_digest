# Productivity Tips для разработки

Вот практические советы для эффективной работы с Claude Code:

## 1. Управление контекстом

### Стратегия "Clean Slate"
```bash
# Перед началом новой крупной задачи
/clear

# Если контекст переполнен, но нужна история
/compact

# Для долгих проектов
/rename проект-фича-дата
# Потом: /resume проект-фича-дата
```

### Когда использовать:
- `/clear` - смена контекста между разными фичами
- `/compact` - продолжение работы с меньшим контекстом
- `/rename` + `/resume` - работа над одной фичей несколько дней

## 2. Эффективные промпты

### ❌ Неэффективно:
```
"Исправь баг"
"Сделай лучше"
"Оптимизируй"
```

### ✅ Эффективно:
```
"В src/auth.py:42 NullPointerException при пустом пароле.
Добавь проверку и верни ValidationError как в src/validators.py"

"Функция process_data() в core.py работает 5 сек на 1000 элементах.
Оптимизируй до <1 сек используя батчинг или кэширование"

"Реализуй JWT аутентификацию:
- POST /auth/login → возвращает access + refresh токены
- Middleware для проверки токенов
- Refresh endpoint для обновления
- Используй библиотеку PyJWT
- Следуй паттерну из существующих middleware в src/middleware/"
```

## 3. Структурирование работы

### Для больших задач:
```
1. "Распиши план реализации фичи X в виде чеклиста"
2. Получаешь детальный план
3. Работаешь по пунктам
4. Используй /todos для трекинга
5. /compact между крупными этапами
```

### Для рефакторинга:
```
1. "Найди дубликаты кода в src/"
2. "Анализируй complexity метрик для module X"
3. "Предложи план рефакторинга"
4. Применяй по частям
5. После каждого шага - запускай тесты
```

## 4. Использование slash команд

Создай алиасы для частых задач:
```bash
# Вместо: "Запусти тесты и проверь что всё работает"
/test

# Вместо: "Посмотри на мои изменения и найди проблемы"
/review

# Вместо: "Помоги отладить эту ошибку..."
/debug "StackTrace тут"
```

## 5. Workflow паттерны

### Morning Routine:
```bash
cd ~/projects/myapp
/resume myapp
/todos
# Продолжаешь с места где остановился
```

### Feature Development:
```bash
/clear  # Свежий старт
/rename myapp-auth-feature

"Реализуй OAuth2 аутентификацию с Google"
# ... работаешь над фичей ...

/test  # Проверяешь
/review  # Ревью перед коммитом

git add . && git commit -m "feat(auth): add Google OAuth2"
```

### Bug Fixing:
```bash
/debug "Error: NullPointerException at line 42..."
# Claude анализирует и предлагает фикс
# Применяешь исправление
/test  # Проверяешь что пофиксилось
```

### Code Review:
```bash
git checkout feature-branch
/review
# Claude даёт feedback
# Исправляешь замечания
```

## 6. Keyboard Shortcuts

Запомни основные:
- `Ctrl+R` - поиск по истории команд
- `Ctrl+L` - очистить экран (сохраняет контекст)
- `Backslash+Enter` или `Shift+Enter` - многострочный ввод
- `Ctrl+C` - отменить текущую операцию

## 7. Оптимизация стоимости

### Выбор модели:
- **Haiku** - простые правки, форматирование, тривиальные вопросы
- **Sonnet** (default) - 95% задач
- **Opus** - сложная архитектура, хитрые баги

### Экономия токенов:
```bash
# Регулярно
/compact  # Экономит ~70% токенов

# Между большими фичами
/clear

# Точные промпты = меньше итераций = меньше токенов
```

## 8. Session Management

### Именование сессий:
```
проект-модуль-фича
myapp-auth-oauth2
bot-telegram-payments
website-frontend-redesign
```

### Организация:
```bash
# Утром: возобновить вчерашнюю работу
/resume myapp-auth-oauth2

# Переключение между проектами
/clear
cd ~/other-project
/resume other-project-feature

# Вечером: сохранить прогресс под понятным именем
/rename myapp-auth-oauth2-wip
```

## 9. Debugging Workflow

### Систематический подход:
1. Воспроизведи проблему
2. Минимизируй пример (убери лишнее)
3. Опиши:
   - Что ожидал
   - Что получил
   - Стек ошибки
   - Что уже пробовал
4. `/debug "полное описание"`
5. Примени фикс
6. `/test` - убедись что пофиксилось
7. Добавь тест чтоб не повторилось

### Для сложных багов:
```
"Изучи flow выполнения от точки A до точки B"
"Логируй промежуточные значения"
"Добавь assert'ы для проверки инвариантов"
```

## 10. Best Practices

### DO:
✅ Давай точные, детальные промпты
✅ Используй /compact регулярно
✅ Разбивай большие задачи на маленькие
✅ Тестируй после каждого изменения
✅ Коммить часто, маленькими порциями
✅ Используй /rename для важных сессий

### DON'T:
❌ Не теряй контекст без необходимости (/clear в середине работы)
❌ Не давай расплывчатые задачи
❌ Не делай всё в один коммит
❌ Не игнорируй ошибки "разберусь потом"
❌ Не пиши код без тестов для критичной логики


## 12. Когда НЕ использовать Claude Code

Claude Code отлично для:
- Написания нового кода
- Рефакторинга
- Debugging
- Code review
- Изучения кодовых баз

НО не подходит для:
- Pixel-perfect UI design (используй Figma)
- Сложные визуальные эффекты (делай сам, итеративно)
- Микрооптимизации (профайлер лучше)
- Routine операции без мышления (используй скрипты)

## Итого: принципы эффективной работы

1. **Контекст** - управляй им активно (/compact, /clear, /resume)
2. **Точность** - давай детальные промпты с контекстом
3. **Итеративность** - маленькие шаги, частое тестирование
4. **Автоматизация** - hooks, slash commands, скрипты
5. **Документация** - CLAUDE.md в каждом проекте

Применяй эти принципы и работа с Claude Code станет в разы эффективнее!
