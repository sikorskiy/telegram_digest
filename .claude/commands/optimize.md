# Performance Optimization

Оптимизируй производительность: $ARGUMENTS

## Процесс:

### 1. Профилирование (Measure First!)
- Добавь замеры времени выполнения
- Используй профайлер:
  - Python: `cProfile`, `line_profiler`
  - Node.js: `--prof`, `clinic.js`
  - Go: `pprof`
- **Baseline**: текущая производительность (время, память)

### 2. Найди узкие места (Bottlenecks)
- **Database**:
  - N+1 queries (используй JOIN или batch loading)
  - Отсутствие индексов
  - SELECT * вместо конкретных полей
  - Тяжёлые transactions
- **Algorithms**:
  - O(n²) алгоритмы (вложенные циклы)
  - Избыточные вычисления
  - Неэффективные структуры данных
- **Memory**:
  - Большие объекты в памяти
  - Memory leaks
  - Копирование вместо ссылок
- **I/O**:
  - Синхронные операции (блокируют)
  - Много мелких запросов
  - Отсутствие кэширования
- **Network**:
  - Много HTTP запросов
  - Большие payload'ы
  - Отсутствие compression

### 3. Предложи оптимизации
- **Кэширование**:
  - Redis/Memcached для часто запрашиваемых данных
  - LRU cache для функций
  - HTTP cache headers
- **Батчинг**:
  - Группировка DB запросов
  - Bulk inserts/updates
  - DataLoader pattern
- **Асинхронность**:
  - async/await для I/O операций
  - Worker threads для CPU-heavy задач
  - Message queue для фоновых задач
- **Database**:
  - Индексы на часто запрашиваемые поля
  - Денормализация где нужно
  - Пагинация вместо загрузки всех данных
- **Algorithms**:
  - Замени O(n²) на O(n log n) или O(n)
  - Используй хэш-таблицы для поиска O(1)
  - Мемоизация для рекурсивных функций
- **Lazy Loading**:
  - Не загружай то, что не используется
  - Code splitting в фронтенде
  - Defer загрузку некритичных данных

### 4. Реализуй изменения
- Делай по одной оптимизации за раз
- Измеряй после каждого изменения
- Сравнивай с baseline

### 5. Измерь улучшение
- **Метрики**:
  - Время выполнения: было X мс → стало Y мс
  - Использование памяти
  - Количество DB запросов
  - Throughput (requests/sec)
- **Цель**: 2-10x improvement (иначе не стоило усилий)

## Важно:
- Оптимизируй только если есть **реальная** проблема
- "Premature optimization is the root of all evil" - Donald Knuth
- Сначала измерь, потом оптимизируй
- Не жертвуй читаемостью ради микрооптимизаций
- Профилируй на реалистичных данных, не на mock'ах

## Red Flags (когда точно нужна оптимизация):
- Пользователи жалуются на медленную работу
- Timeout'ы на продакшене
- Высокие счета за инфраструктуру
- CPU/Memory usage > 80% постоянно
